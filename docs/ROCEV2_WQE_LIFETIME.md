## Actual issued context, not incoming-packet authority

The complete588-bit authorized original WR and trusted local/peer IP/peer QPN
are captured before SQ issue. Full identity/authorization/shape/interval ends
are checked; no shortened key/address/QPN becomes authority. Failed fetch/MR
denial/error-CQE routing still needs its separate trusted queue-shadow owner;
this module accepts only the positive authorized READ/WRITE path.

Its passive TX port observes ACCEPTED beats on this WR's dedicated post-
integrity HLS IP stream, NOT arbitrary host TX. It verifies whole accepted
frame shape/length, IPv4 checksum, trusted source/destination, peer QPN,
operation/PKey/TVer/pad/reserved policy and exact full RETH remote VA/key/length.
The expected response PSN comes from the actual OWN transmitted BTH. TX ICRC
must already have been checked/generated by the actual upstream integrity
stage; this observer is not a second ICRC engine or an outbound policy filter.

Only after matching the complete emitted request does it offer the full saved
context/IP/PSN to the response guard. `response_admission_ready` remains0until
that expectation is accepted. An upstream owned-response FIFO MUST hold any
early response while0, not feed it into an unowned/discarding RX guard. The
actual shared transport/ingress/native parent wiring is still unfinished.

## Separate proofs, prepared ticket and actual commit

Independent evidence is retained, with exact full588-bit identity wherever
the interface provides it:

- memory status/visibility from the real executor/backend;
- protected response opcode/PSN/AETH and the full original context;
- actual40-bit HLS ACK kind/QPN/PSN/padding;
- actual full-owner MAC send completion from a genuine native tag/epoch mapper;
- current real memory AND transport drain.

A WRITE source memory status may precede request transmission. A READ memory
status cannot precede issue. HLS ACK may precede data commit and is consumed
without treating it as WR completion or blocking the HLS pipeline forever.
No subset of those proofs yields a CQ ticket. Unknown/misowned/duplicate/error
proofs fault and retain all-QP guards; exact backend/MAC error is recorded,
never converted into success or recovery.

The prepared full-context CQ ticket remains stable through stalls/faults.
Its acceptance is NOT publication, WR completion or permission to unpin. Only
a later exact full-owner successful CQ commit, with both real drains still
true and no concurrent bad proof, releases this whole-WR guard. A same-edge
bad ACK/proof cannot outrun fault capture and acknowledge an otherwise exact
commit. For unsignaled WRs the private accounting/commit still exists; a real
publisher must honor original flags instead of inventing a user CQE.

This two-phase private contract still needs a REAL CQ event/ring/IRQ/driver/
provider binding. A real publisher must not release kernel MR/QP references
merely upon ticket acceptance. Real MAC completion correlation, HLS drain and
fault/abort/flush/retry/reset safety remain required; no default-success proof,
CQ callback or empty RDMA device is introduced by these ports.
